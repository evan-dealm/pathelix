## Bugs corrigés

1. **`planningStore.ts` — undo/redo saute un niveau d'historique et ne peut jamais revenir
   exactement à l'état après la dernière action.** Bug hérité, documenté mais non corrigé lors
   de la session de test manuel du 16 août 2026 (`TEST_MANUEL_PROGRESSION.md` bug #5). Root
   cause : `_history` ne stocke que des snapshots pré-action ; `undo()` décrémentait l'index
   avant de lire au lieu de lire puis décrémenter, sautant un niveau ; l'état réel après la
   dernière action n'était jamais capturé, rendant certains redo définitivement impossibles.
   Corrigé avec un nouveau champ `_tip` capturé paresseusement. Deux tests existants
   asseraient directement le bug (comportement faux accepté comme "normal") — corrigés avec
   justification inline, 4 nouveaux tests de régression ajoutés. Commit `e785ca2`.

## Risques résiduels connus (non liés aux dépendances)

Déjà documentés avant cette session, toujours d'actualité, listés ici pour un état des lieux
complet :

- **Génération PDF cassée en production** (`/api/tours/pdf`, probablement `/api/reports/pdf`)
  — dual package hazard `@react-pdf/renderer` sous le bundler Next.js. Nécessite une refonte
  architecturale (worker dédié). Voir `docs/deploiement.md` §4.
- **Notes de planification jamais partagées entre dispatchers** — stockage `localStorage`
  uniquement, pas de modèle DB. Gap fonctionnel, pas un bug de sécurité. Scope produit, pas
  traité cette session (nécessiterait un nouveau modèle Prisma + route API + migration DB —
  jugé hors périmètre d'une correction ponctuelle).
- **Gating UI des permissions granulaires incomplet** — 7 des 11 permissions inertes pour un
  dispatcher car leur onglet est bloqué au niveau rôle. Backend correctement protégé
  (vérifié), donc UX trompeuse, pas une faille. Décision produit à trancher, non tranchée
  unilatéralement cette session.
- **Race condition sync-queue chauffeur offline** (`AUDIT_BUGS.md` N23) — verrou non partagé
  entre page et Service Worker.
- **HALT Trackdéchets actif** — aucun appel API TD en production sans validation manuelle,
  voir `docs/deploiement.md` §5.
- **Next.js 16 non appliqué** — évalué, différé, déjà documenté avant cette session.

Aucun de ces éléments n'a été tranché unilatéralement cette session lorsqu'il s'agissait d'une
décision produit plutôt que d'un bug — conformément à la préférence connue du projet de ne pas
imposer de choix produit sans les soumettre à l'utilisateur.
